# Using the components

## Pick by intent

| You need                                              | Use                                        |
| ----------------------------------------------------- | ------------------------------------------ |
| The one main action of a view                         | `Button variant="primary"`                 |
| Any other action                                      | `Button` (secondary is the default)        |
| A quiet action that repeats, like "Add milestone"     | `Button variant="ghost"`                   |
| To go to another page or a Site's Address             | `ButtonLink`, never a `Button` with a push |
| A file selected by browsing or dropping              | `FilePicker`, with explicit MIME types and a size limit |
| Text entry                                            | `Field` with `Input` or `Textarea`         |
| One of five or more options, like a Timezone          | `Field` with `Select`                      |
| One of two to four options, like the Sex              | `SegmentedControl`                         |
| A fact the person states: "The baby has been born"    | `Checkbox`                                 |
| One step that changes a lot at once, like the birth   | `FullPageDialog`, opened from a `Button`   |
| A yes or no before something hard to undo             | `ConfirmDialog`                            |
| A setting that shows or hides something               | `Switch`                                   |
| A Site's Palette or Font                              | `PalettePicker`, `FontPicker`              |
| A Site's Languages                                    | `LanguagesPicker`                          |
| A text in every Language of a Site                    | `PerLanguageField`                         |
| One emoji, like a Milestone's                         | `EmojiPicker`                              |
| The outcome of an action: saved, sent, failed         | `StatusMessage`                            |
| A status or property of the thing beside it           | `Badge`, never a Button styled as a label  |
| Requirements that tick off, like a password's rules   | `Checklist`, tied to its control           |
| Work in flight, outside a Button                      | `Spinner`, the only spinner there is       |
| The Platform's name and mark                          | `Logo` (`PageShell` already shows it)      |
| A group of related settings with a heading            | `Card title="…"`                           |
| Space between siblings                                | `Stack`                                    |
| The playful circles behind a whole page               | `JoyBackground`, once per page             |

## Buttons

- **One primary per view.** If two actions look equally important, one of them is not.
- **Say what happens.** A verb, then what it acts on: "Create Emma's page", "Send notification". No "OK" or "Submit".
- **Do not disable a button while work is in flight.** Pass `loading` and an in-progress label ("Saving…"): the button
  shows the `Spinner`, keeps its focus, says it is busy and ignores presses.
- **Navigation is a link.** `ButtonLink` keeps opening in a new tab and reads as a link to screen readers.

```tsx
<Stack direction="row" gap={3}>
  <ButtonLink href={`/dashboard/${slug}`}>Back</ButtonLink>
  <Button variant="primary" type="submit" loading={saving}>
    {saving ? 'Saving…' : 'Save changes'}
  </Button>
</Stack>
```

## Forms

- **Every control has a label.** Wrap it in a `Field`, which generates the id and ties the label, hint and error to
  the control. When the control's place in a row already says what it is, like a Milestone's date beside its emoji,
  give the label to screen readers only with `labelHidden`.
- **A text in every Language of a Site**, like a Milestone's label or the Birth message, goes in a `PerLanguageField`:
  it takes the texts by Language, calls `onChange(lang, text)`, and lays out and labels one control per Language,
  which its `children` draws.

```tsx
<PerLanguageField
  label="Page name"
  languages={languages}
  value={pageName}
  onChange={(lang, text) => setPageName({ ...pageName, [lang]: text })}
  errors={errors}
>
  {({ lang, value, onChange }) => <Input lang={lang} value={value} onChange={(e) => onChange(e.target.value)} />}
</PerLanguageField>
```
- **Never write an `id` by hand.** Biome fails the build on one. `Field` and `useId()` make unique ids.
- **Mark the optional fields**, with `optional`, not the required ones. The marker uses `Badge variant="plain"`: sentence case, regular weight, and the label's color.
- **An error says what happened and how to fix it**: "Someone got there first. Try emma-2026.", not "Invalid slug".
- **Validate on one action, and clear an error the moment it is fixed.** A form checks its fields when the person
  submits it, never while they are still typing: before that nothing turns red. A `Checklist` may tick requirements
  off as they type, but leaves the unmet ones neutral until the submit. Once an error shows, the form checks that field
  again on every edit, and the error goes away as soon as its rule is met, without another submit. An error only the
  server can find, like a Slug already taken, stays until the next submit.
- **Move focus to the first field in error** after a failed submit, so the keyboard and screen readers land on it.
- **Say an error once.** When something else on screen already shows the problem, like the rules a `Checklist` flags,
  give the Field's error to screen readers only with `errorForScreenReaders`.
- **Put the form's outcome in a `StatusMessage`** next to its submit button. Keep the `StatusMessage` mounted and change
  its children, or screen readers miss the announcement.

```tsx
<Field label="Page address" hint={`Your page will be at ${address}`} error={slugError} liveHint required>
  <Input value={slug} onChange={(e) => setSlug(e.target.value.toLowerCase())} />
</Field>
<StatusMessage tone={failed ? 'danger' : 'success'}>{message}</StatusMessage>
```

## Layout

- **Start from the phone.** Lay a page out in one column first. Add columns at `min-width: 60rem` (wide screens)
  where they help, as the Public page demo does with the Countdown beside the name.
- **Use the width tokens**: `--content-narrow` for a sign-in card, `--content-medium` for a form, `--content-wide`
  for a Dashboard. Side padding is `--gutter`, which grows from 16px on a phone.
- **Let rows wrap.** `Stack direction="row"` wraps when the screen runs out of room; never let a page scroll sideways.

## Theming

- **Never set a color, size or font in a page.** Use a token, or a component that already uses one.
- The Platform's pages need nothing: the root layout writes the Platform's theme on `:root`. Wrap the page in a
  `PageShell`, which brings the wordmark, the circles and one `<main>`.
- A Public page writes its Site's theme on `:root` with `<style>{rootTokenCss(themeStyle(site.theme))}</style>`,
  which comes after the layout's and wins, and loads `googleFontsHref([getFont(site.theme.font)])`.
- A part of a page in another theme, like the onboarding preview, sets the tokens inline:
  `style={themeStyle(theme)}`.
- A page that shows the `FontPicker` loads every Font: `googleFontsHref(FONTS)`.

## Words

The Owner is an expecting parent: talk to them like a friend who is happy for them.

- Warm, short, sentence case. "Make it yours", "Your page is up to date".
- Talk about **their** baby and **their** page, by name when you have it: "Create Emma's page".
- No "please", no blame, no jargon. "Couldn't save your changes. Try again." Never "Error 500".
- Use the [glossary](https://github.com/mariotsi/baby-loader-as-a-service/blob/staging/GLOSSARY.md) terms in code
  and keep the copy plain: the code says Slug, the page says "page address".
